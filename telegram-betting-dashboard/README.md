# Telegram 多账号、多群下注控制台

## 多账号使用方法

网页顶部是账号切换栏。原来的 Telegram 登录自动作为“默认账号”，原有群、流水和日志不迁移、不丢失。

1. 点击“＋ 添加账号”，填写备注和含国家区号的手机号。备注可以不填。
2. 新账号自动使用当前程序 `.env` 中的同一套 Telegram API，无需再次输入 API ID 或 API Hash。
3. 点击发送验证码，再在网页输入 Telegram 验证码；开启两步验证的账号会继续要求输入密码。验证码和密码只用于当前登录，不会保存。
4. 添加完成后从顶部切换账号，再为它添加群。每个账号拥有独立 Telegram 连接、群配置、数据库、每局结果和日志。
5. “移除账号”只适用于后来添加的账号。移除后会断开连接，并把该账号的本地文件移到 `data/已移除账号/` 归档；不会删除 Telegram 账号。默认账号不可移除。

所有账号共用程序启动时从 `.env` 读取的 API 配置，新增账号配置中不再重复保存 API Hash。账号配置位于 `data/accounts/`。不要把这里的 `.session`、`accounts.json` 或归档目录发送给别人。

## 多群使用方法

先关闭旧程序，再双击原来的启动文件。一个网页控制多个 Telegram 账号及各自的群。

1. 原来的群自动出现在“我的群”，原数据库、流水和每局结果保留。
2. 点击“＋ 添加群”，从当前账号已加入的群中选择。在 Telegram 中点开机器人的资料页，复制 `@用户名` 并粘贴到“游戏机器人 @用户名”即可；无需查询数字 ID。保存时自动核验机器人身份并记录固定数字 ID。原数字 ID 仍可使用，页面也会从最近 150 条消息中自动识别候选。注意复制用户名，而不是显示昵称。
3. 为新群选择“定时开盘”或“下注后掷骰”；即时模式还能设置每次开奖到下一单之间的等待秒数。下注发送位置可选“当前群内发送”或“机器人私聊发送”。填写金额范围 X～Y、流水目标 N，并勾选“大、小、单、双”中的一项或多项。新群默认暂停，核对后点击“恢复此群”。
4. 点击群卡片切换：下方金额、下注选项、目标、下注记录、余额、日志、重置和导出均只针对当前群。
5. “全部暂停”停止当前所选账号下所有群的后续下注，继续记录回执和开奖。“停止整个程序”关闭全部账号、全部群和本地网页。已经发出的消息不会撤销。

每个群独立记住开奖方式、金额范围、下注选项、流水目标和暂停状态，重启后继续使用。所有群使用本次启动选定的真实或模拟模式，新增群不会因添加操作直接下注。暂停状态与流水目标按运行模式保存。跨天仍需分别点击流水重置。

所有群都可以点击“删除此群”移除。删除会先停止该群的任务，再把数据库、日志和每局结果移动到账号目录下的“已移除群”文件夹；不会退出 Telegram 群。旧版启动时选定的初始群会生成历史数据库快照后从运行列表移除，以后仍可通过“添加群”重新加入。

程序每 3 分钟检查一次所有已连接账号和群。对“用户要求运行”、尚未达到流水目标、且 3 分钟没有新发送记录的群，会刷新群连接、回查最近 100 条群消息及相关机器人私聊，再恢复后续循环。用户手动暂停的群不会被自动启动；无法确认的上一单会继续保留为待核对，避免重复发送。

程序会在本地时间每个整点和半点（例如 12:00、12:30、13:00、13:30）汇总所有账号和群的连接状态、余额、流水、结算、输赢和待确认订单，并默认使用 `@aghaststar` 发送到配置的汇报群。默认不附带逐群明细，避免消息过长。可在 `.env` 中用 `TG_REPORT_ACCOUNT` 和 `TG_REPORT_CHAT` 覆盖发送账号与目标群；邀请链接目标会在首次汇报时由发送账号自动加入。

网页顶部的“半小时汇报设置”可以开启或关闭定时汇报、选择带用户名的发送账号、修改目标群，并用“包含各群明细”决定是否追加逐群数据，也可手动点击“立即汇报”。网页保存的设置优先于 `.env`，重启后继续生效。

### 群内开奖、机器人私聊下注

公群禁言但仍发布开盘和开奖结果时，先选择该群并暂停，再在“控制设置 → 下注发送位置”中选择“机器人私聊发送”并保存。脚本仍只从原群读取期号、封盘和开奖结果，但把 `大10` 等下注指令发送到该群所配置机器人的私聊，并从私聊读取下注成功或失败回执。恢复前请先手动打开机器人的私聊并点击一次“开始 / Start”，确认账号允许给机器人发消息。

如果多个群共用同一个机器人，脚本优先按机器人回复引用的原下注消息 ID 归属回执；其次使用回执中完整的下注指令。无法唯一判断时不会把回执记到任意群，相关订单会按原有超时保护自动暂停，防止串群记账。开奖仍以各自群内消息为准。

原群文件仍在 `data/`；新增群文件在 `data/groups/群ID/`，包括 `rounds.sqlite3`、`每局结果/期号.txt` 和导出后的 `rounds.csv`。不同群即使期号相同也不会覆盖。新增群配置保存在原数据库的 `group_profiles_v1` 设置项中，不要删除原数据库。

新增群必须使用当前脚本支持的玩法和消息格式（`SL...` 期号或 Telegram 原生骰子、`大10 小10 单10 双10` 这类指令及下注回执）。其他玩法需要另写解析规则。多个群如共用同一个钱包，显示的余额可能属于同一钱包，不能直接相加。该版本已用离线假群验证，不代表已验证每个实际群的机器人规则。

群连接失败会单独显示错误和“重试连接”，其他已加载的群继续处理消息。原数据库绑定原群；不要通过修改 `.env` 的 `TG_GROUP` 来替换原群，应通过网页添加。

这个脚本监听指定 Telegram 群和指定游戏机器人。定时开盘群在机器人发布新的 `SL...` 期号时下注；下注后掷骰群在恢复后主动下注，并等待这一单对应的 Telegram 骰子结果，结算后才开始下一单。累计成功下注金额（总流水）达到目标 N 后自动停止后续下注，但继续监听和记录。

### 两种开奖方式

- `定时开盘`：适合机器人先公布期号、再等待玩家下注、最后统一开奖的群。原有群默认保持此模式。
- `下注后掷骰`：适合 1888 这类先发送下注指令、机器人随后投骰子的群。同一群始终最多只有一单在等待；收到骰子并记录结果后，等待该群自定义的 1～3600 秒再开始下一单，默认 5 秒。
- 即时模式超过 30 秒（或回执超时设置的 3 倍，取较大值）未收到骰子会自动暂停，防止网络延迟时连续发送。重启发现上一单未结算也会保护性暂停。
- 即时模式在模拟运行中不会真实发送，所以无法触发机器人骰子；它只生成一条模拟记录后自动暂停。要验证完整循环必须使用真实运行，并先用小额和较低流水目标测试。

## 已实现

- 启动时输入随机金额下限 X、上限 Y 和总流水目标 N。
- 每个新期号只随机一次，实际采用的金额会和期号一起保存，重复消息不会重新随机。
- 运行中可在网页分别修改各群的下注组合和金额范围；上下限相同即固定金额。
- 累计流水达到或超过 N 时自动暂停，不会再发送新的下注消息。
- 流水从数据库中累计，关闭或重启脚本不会清零。
- 每个新期号只处理一次；重启后仍由 SQLite 唯一期号防止重复下注。
- 只信任固定群 ID 和固定机器人 ID，其他群成员的相似文字不会触发下注。
- 等待机器人的“下注成功”或“投注无效”回执。
- 回执超时或发送异常时自动暂停，不会反复补发同一期。
- 记录开盘、下注指令、发送状态、回执余额、冻结金额、封盘、骰子、输赢、净额和估算结算余额。
- 支持查询最近记录、累计结果和导出 CSV。
- 顶部可切换多个 Telegram 账号；每个账号和群的数据、控制状态及消息路由完全隔离。
- 每个群可独立选择群内下注或“群内监听开奖、机器人私聊下注”。
- 默认是模拟模式；双击“真实运行.cmd”或使用 `--live` 后，连接成功即自动运行并打开 UI，无需输入确认文字。

## 安全准备

此前发到聊天中的 `api_hash` 不应继续使用。请到 `my.telegram.org` 检查并更换或重建应用凭据。不要把新的 `api_hash`、登录验证码、两步验证密码或 `.session` 文件发送给任何人。

复制 `.env.example` 为 `.env`，然后只在自己电脑上填写：

```text
TG_API_ID=...
TG_API_HASH=...
TG_GROUP=
TG_GAME_BOT_ID=
TG_ACK_TIMEOUT=10
TG_PROXY_TYPE=socks5
TG_PROXY_HOST=
TG_PROXY_PORT=
TG_PROXY_USER=
TG_PROXY_PASSWORD=
DASHBOARD_PORT=8765
BET_MIN_AMOUNT=
BET_MAX_AMOUNT=
BET_STOP_TURNOVER=
BET_START_BALANCE=
```

`TG_GROUP` 和 `TG_GAME_BOT_ID` 可以先留空。首次运行时程序会列出群聊和机器人候选，让你在本机选择。确认后可把显示的数字 ID 填回 `.env`，后续无需重复选择。`BET_...` 也可以留空，程序会在每次启动时询问。

## v2rayN 代理

脚本启动时会检查 v2rayN 常见的本地 SOCKS5/混合端口 `10808、1080、10809、7890`，只有完成 SOCKS5 握手才会自动使用。启动输出会显示实际选中的代理。

如果没有自动检测到，可在 `.env` 明确填写，例如：

```text
TG_PROXY_TYPE=socks5
TG_PROXY_HOST=127.0.0.1
TG_PROXY_PORT=10808
TG_PROXY_USER=
TG_PROXY_PASSWORD=
```

这里填写的是 v2rayN 的本地监听端口，不是远程 VLESS 节点的服务器端口，也不要把节点 UUID、私钥等内容写进脚本。

## 本地网页控制面板

Telegram 登录和群聊确认完成后，程序会自动打开：

```text
http://127.0.0.1:8765/
```

控制面板只监听本机地址，不会公开到局域网或互联网。页面每两秒自动刷新，包含：

- 运行或暂停状态、真实/模拟模式、当前群聊；
- 总流水进度、最新一局、余额、净额和命中率；
- 最近80期下注记录和最近100条事件日志；
- 暂停、恢复、修改大/小/单/双组合、选择群内或机器人私聊下注、修改随机金额、修改流水目标；
- 导出 CSV 和安全停止程序。

如果 8765 已被其他程序占用，会自动选择一个可用端口，并在黑色窗口显示实际网址。关闭网页不会停止脚本；点击网页中的“停止整个程序”或在黑色窗口按 `Ctrl+C` 才会停止。更新后请先退出旧版本，避免同时打开两个运行实例。

## 先用模拟模式核对

复制 `.env.example` 为 `.env`，在本机填写凭据，然后双击 `模拟运行.cmd`。

也可以在 PowerShell 中运行：

```powershell
.\runtime\python\python.exe tg_big_bet.py
```

首次登录由 Telethon 在本机终端要求输入手机号、Telegram 验证码和可能存在的两步验证密码。程序不会把这些内容写入数据库。

模拟模式会读取实时消息、识别期号、生成单项随机金额并显示完整组合指令，但不会向群里发送。模拟下注总额同样会累计为模拟流水，用于测试“达到 N 自动停止”。`BET_START_BALANCE` 只影响虚拟余额显示，不影响流水。

建议至少观察若干完整期次，确认以下内容全部正确：

1. 新期号只识别一次；
2. 骰子 4、5、6 为“大”，1、2、3 为“小”；
3. 骰子 1、3、5 为“单”，2、4、6 为“双”；
4. 选中的机器人 ID 确实是游戏机器人；
5. 群里的投注格式支持 `大10 单10` 这种同一消息内的多项指令。

## 开启真实发送

确认模拟记录正确后：

双击 `真实运行.cmd`，或者运行：

```powershell
.\runtime\python\python.exe tg_big_bet.py --live
```

脚本显示运行信息后直接打开 UI 并开始监听，不再要求输入“我确认自动下注”。首次登录或会话失效时仍需要 Telegram 验证码。已选定的群聊和机器人会记住，后续启动自动使用；`.env` 中明确填写的群和机器人优先。

## 新一轮流水与目标

在控制面板填写“本轮流水停止目标”，然后点击“流水归零并设置新目标”。本轮流水从零开始，目标和重置位置保存到数据库，重启后仍然有效。重置后保持暂停，点击“恢复下注”开始新一轮。

历史下注、每局文本和历史总流水全部保留；记录表中的流水仍为历史累计值。真实与模拟模式分别重置。重置前已发送的订单，即使回执延迟到达，也只归入历史总流水。跨天不会自行重置，需要点击按钮。仅修改目标可用“保存流水目标”，不会归零。

网页保存的目标优先于 `.env` 的默认值；需要从命令行覆盖时可使用 `--stop-turnover`。

## 操作入口与数据文件

多群版本统一使用网页控制，不再接收黑色窗口中的单群命令。每个群可独立勾选“大、小、单、双”任意组合；保存后从下一条新开盘消息开始生效，不补投之前跳过的期号。

金额范围是“单个选项”的金额。比如勾选“大＋单”，本期随机到 10，脚本发送 `大10 单10`，本期总下注和流水为 20。勾选四项、单项 10 时，本期总流水为 40。组合中一部分中、一部分未中且净额为零时，结果显示“持平”。

详细数据保存在：

- `data/tg_big_bet.sqlite3`：完整结构化记录；
- `data/tg_big_bet.log`：运行日志；
- `data/每局结果/SL期号.txt`：每一期单独的人类可读结果文件；
- `data/rounds.csv`：在原群页面点击“导出 CSV”后生成；新增群导出到自己的目录；
- `data/tg_big_bet.session`：Telegram 登录会话，必须像密码一样保护。

每局结果文件会在下注、机器人回执和开奖时持续更新，最终内容包括期号、发送指令、中了或未中、本局计入流水、累计流水、余额、骰子、净额和各阶段时间。例如：

```text
期号：SL654928300501070
发送：大20 单20
下注选项：大,单
单项金额：20
结果：中了
本局计入流水：40
累计流水：1200
余额：5380
```

## 余额口径

机器人“下注成功”回执中的余额通常是全部下注金额冻结后的可用余额。脚本按每个选项 1:1 返奖估算结算后余额：

- 每个命中的选项返还 `2 × 单项金额`；
- 每个未中的选项不返还；多项结果的净额是所有选项盈亏之和。

余额仍作为核对字段记录，但不再作为停止条件。如果机器人改变余额口径，应以机器人实际余额为准并调整计算规则。

## 总流水口径

- 真实模式：只累计机器人明确回复“下注成功”的实际下注金额；发送失败、超时、被拒绝和暂停跳过的期次不计入。
- 模拟模式：累计每个新期号的全部选项金额；总流水等于单项金额乘以勾选项数。
- 达到目标的最后一笔可能让累计流水略高于 N，例如当前流水 95、随机下注 10，则会在流水 105 时停止。
- 真实模式和模拟模式分别统计，数据保存在同一个 SQLite 数据库中，重启后继续累计。

## 重要限制

- 脚本不会绕过封盘；收到拒绝回执后不会重试当期。
- 如果机器人没有正确引用下注消息，脚本只能用“完整指令＋最近待确认订单”匹配回执，因此应先充分运行模拟模式。
- 回执或骰子超时会先回查最近消息。仍无法确认时不会重发同一订单，网页会显示“自动恢复等待中”，后续每 3 分钟再次核对。
- 即时模式的订单连续 3 分钟仍没有骰子时，会标记为“失联订单已跳过”并继续下一单；也可以点击“恢复此群”立即跳过。旧订单后来才返回的回执或骰子只写入日志，不会计入新订单。
- 使用机器人私聊下注前，应先手动打开机器人并点击 Start；若多个群共用同一机器人且回执既不引用原消息也不含完整下注指令，脚本会忽略无法唯一归属的回执并触发超时暂停。
- Telegram API 自动化应遵守 Telegram 及群聊规则，频繁或异常发送可能触发账号限制。
- 选择任何单项或组合都不会产生数学优势；同时选择互相对立的“大＋小”或“单＋双”通常只会增加流水。脚本只负责自动化和留痕，不保证盈利。
- 真实运行前必须先用模拟模式确认目标机器人确实接受空格分隔的组合指令，并核对实际赔率；当前结算估算按每项 1:1、无手续费计算。
